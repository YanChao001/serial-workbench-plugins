## 推荐阅读路径

- **了解参考插件**：[README](../README.md) → 对应插件 README。
- **开发与收录**：[独立作者入口](./plugin-authoring.md)完成最小示例 → [开发指南](./development.md)迭代插件 → [测试规范](./testing.md#按改动选择检查)验证受影响行为 → [贡献流程](../CONTRIBUTING.md)准备收录审查。
- **签名发布**：从已审核源码按 [发布与管理](./publishing.md) 固定宿主提交、完整构建验签、发布并核对线上结果；权限、来源和密钥变更同时查 [安全规范](./security.md)。

## 维护规则

工程文档使用中文、UTF-8 和可读链接。README 保留介绍与最短入口；架构解释运行方式，开发指南解释操作，测试规范说明验证范围，发布指南维护线上操作，安全规范定义审核边界，排障手册按症状连接对应处理。

同一事实在一处定义，其余使用相对链接。工具版本、完整命令清单、插件权限和产物名称链接到配置或源码；跨仓库引用使用宿主仓库链接，支持独立检出。新增长期文档时加入本索引。

通用写作规则见 [写作与免责措辞](https://github.com/YanChao001/serial-workbench/blob/main/docs/README.md#写作与免责措辞)。说明删后不影响操作或判断就删；影响决策时写清具体条件、后果和下一步，放在相关操作旁。保留真实权限、数据和法律边界。

收录项与参考源码按 [listings.json](../listings.json) 区分，`check` 验收范围和 CI 触发以实际 [脚本](../scripts/) 与 [工作流](../.github/workflows/) 为准，发布状态依据实际运行和 Release。具体范围与操作写在对应开发、测试或发布指南。

代码、配置和相应文档同步修改。提交前核对命令的工作目录、shell、环境变量、文件链接和标题锚点。检查结果及适用环境写在 PR 或 Release 中。
