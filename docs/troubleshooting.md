# 市场排障手册

按失败阶段查找下列症状，保留宿主版本、市场提交或 Release、目录修订、插件 ID / 版本、错误码和脱敏日志。发布步骤见 [发布指南](./publishing.md)，安全报告见 [安全规范](./security.md#漏洞与密钥事件)。

## 客户端错误

| 错误码                   | 典型原因                                                | 处理方法                                                |
| ------------------------ | ------------------------------------------------------- | ------------------------------------------------------- |
| `MARKET_NOT_CONFIGURED`  | 仓库或受信公钥未配置                                    | 核对宿主配置与目标仓库、公钥，再重新构建                |
| `MARKET_INCOMPATIBLE`    | 已验签目录使用不支持的 schema                           | 使用配套宿主与目录；签名有效不表示协议兼容              |
| `MARKET_EXPIRED`         | 已签名目录到期                                          | 核对设备时钟；维护者以更高 revision 续签发布            |
| `MARKET_INVALID`         | 签名、结构、时间、大小、哈希异常，或目录回退 / 同号替换 | 保留目录证据，核对信任源、附件、修订和时钟              |
| `MARKET_UNAVAILABLE`     | 网络、超时、缺附件或本机信任记录 I/O 失败               | 核对公开 Release、完整附件、网络与应用数据目录后重试    |
| `MARKET_CHANGED`         | 所选包或来源收据与当前目录不符                          | 刷新后重新审阅并下载，不复用旧收据                      |
| `EXTENSION_INCOMPATIBLE` | 包 / API、最低宿主或注册表版本不兼容                    | 按失败阶段选择配套包 / 宿主；旧注册表使用应用内归档流程 |

旧客户端可能统一显示“市场目录或扩展包校验失败”。先确认正在运行的原生程序版本；前端刷新不能替换 Rust 进程。

### 新目录在旧宿主显示 MARKET_INVALID

旧宿主可能在解析新权限或图标时失败，尚未进入 `minHostVersion` 检查。按 [固定配套宿主](./publishing.md#固定配套宿主) 取得包含所需能力的原生构建，退出旧进程，启动新构建后刷新市场。

### 已验签但仍然不兼容

核对目录 schema、包格式、API、视图与最低宿主，按 [配套宿主要求](./publishing.md#固定配套宿主) 从对应源码重建并签名。

### 某条目仅显示需要新宿主

这是不兼容条目的只读预览或摘要。升级配套原生宿主后刷新；适用条件见 [兼容与演进](./architecture.md#兼容与演进)。

### 自定义界面打不开或只看到旧布局

核对原生宿主提交、HTML 协议 / SDK、已安装插件版本及 UI 哈希，重编、重启宿主并安装新包。连接失败时从“扩展工具”重载，恢复本窗口已报告的字段与检查点。

持续失败时检查 UTF-8、`ui.document`、哈希、授权和 CSP；已展示但正文异常时检查作者脚本。前台加载停滞可重试，控件与 SDK 接线见 [自定义界面开发](./development.md#自定义界面开发)。

### 已推送分支但市场仍是旧内容

客户端读取配置仓库的公开 latest Release。按 [生产发布](./publishing.md#actions-生产发布) 核对 Actions 状态、发布运行、草稿和附件。以下命令只读，仓库名以 [listings.json](../listings.json) 为准：

```sh
gh release view --repo YanChao001/serial-workbench-plugins --json tagName,isDraft,isPrerelease,targetCommitish,publishedAt,assets
gh workflow list --repo YanChao001/serial-workbench-plugins
```

显式刷新重新获取目录；保留的旧展示仍须满足签名有效期才能下载和安装。

### 签名有效但包校验失败

完整 JSON 包的 `packageSha256` / `packageBytes` 与内含 Wasm 的哈希 / 大小都须匹配。常见原因是签名后重打包、格式化 JSON、上传旧附件或清单和模块不符。

运行 `node scripts/verify.mjs <发布目录>` 核对全部包。失败时保留原目录，从审核源码重建并发布更高修订；签名对照与字节要求见 [生产发布](./publishing.md#actions-生产发布)。

### 时间、过期与目录回退

核对设备 UTC 时间。已到期为 `MARKET_EXPIRED`，签发过远或窗口异常为 `MARKET_INVALID`。宿主保留最高修订与 payload 摘要；同号修改或重签应改用 [更高修订续签](./publishing.md#有效期与续签)。

## 原生服务与插件功能

### 新权限或服务不可用

核对已安装清单、授权、启用状态和 [原生服务实现](./development.md#固定原生服务)。禁用、撤权或替换后重新打开当前包。停止等待后，重试前先核对保存、发送或下载的实际状态。

### LAN 监听或连接失败

按 [两台设备操作步骤](../plugins/lan-chat/README.md#两台设备开始聊天) 打开已授权插件。附近设备未出现时，在“连接与设置”填写对方显示的私有 IPv4 和 TCP 端口；`127.0.0.1` 指本机，缺少可用私有 IPv4 时也仅绑定回环地址。

发现使用 UDP `45874`，聊天默认 TCP `45873`。发现端口占用时仍可手动连接；TCP 端口占用则点击“停止通信”后换端口。检查默认网卡、路由、防火墙和无线隔离，发现限于同网段，排除同机多进程。仅验证本机时点击“开始回环测试”。

联系人在握手后出现；“等待送达回执”须等对端原子保存后的 ACK。缺回执时核对对方历史后决定是否重发，并确认两端使用 [配套宿主和线协议](./publishing.md#固定配套宿主)。明文与身份边界见 [安全规范](./security.md#原生服务与外部来源)。

附件失败时按 [附件要求](../plugins/lan-chat/README.md#表情图片与文件) 检查格式、字节与像素额度。缓存满时清理不需要的历史以释放未引用附件；传输中断时检查对端连接、网络与超时。

普通文件以卡片显示，使用“另存为”保存；图片才有预览。另存取消、附件不可用或额度不足时按操作反馈处理，保留聊天记录。

### 切换页面后仍然收信

导航和 iframe 重载保留原生连接。点击“停止通信”结束连接；窗口关闭、撤权与安装变更的回收条件见 [内网通信说明](../plugins/lan-chat/README.md#信任边界与数据)，历史保留。

卡顿、输入被禁用或草稿倒退时，核对包与 SDK 版本，反馈中区分后台查询和手动请求，记录延迟或乱序条件。

### 图源加载、预览或下载失败

核对 [配套宿主和插件版本](./publishing.md#固定配套宿主)，区分图源请求、Wasm 解析、图片获取、句柄失效与解码 / 额度拒绝。接口改版、限流或错误图源会保留旧成功列表；零或少量结果按真实数量显示，下一批过滤已见图片。可稍后重试或切换来源，具体分页与图源规则见 [壁纸说明](../plugins/wallpaper-browser/README.md#图源预览与资源)。

按 [网络连接](../plugins/wallpaper-browser/README.md#网络连接) 核对宿主设置及插件独立授权。未授权代理或命中排除时直连并核验 DNS，Fake-IP 等非公网结果会拒绝；按实际原生传输排查，浏览器可能采用不同代理。

原站可能移除文件、要求 Cookie、跳转或返回不支持格式。资源失效时重新获取，预算满时释放无用资源，另存取消按取消处理。分别记录列表、预览、另存和导入结果，验证范围见 [服务验收](./testing.md#固定原生服务验收)。

### 图片已加入图库但不是原始文件

“加入图库”重绘压缩图片，“保存高清图”另存已验证文件；各站点的高清适配和完整尺寸获取方式见 [壁纸说明](../plugins/wallpaper-browser/README.md#图源预览与资源)。图库满或 revision 冲突时保留原数据，刷新后重新选择。背景作用于本应用，移除当前背景时确认并恢复纯色。

### 游戏没有声音或返回后暂停

Web Audio 需用户点击解锁，检查静音和系统音量；无音频支持仍可游玩。失焦、隐藏和长帧会暂停，返回后手动继续，不补算离开时间。保存取消保留棋局；长期保留使用宿主会话导出，纪录保存不是棋局备份。

## 本地构建与真实 Wasm 校验

### 找不到 `extension-tool`

`STARTER_EXTENSION_TOOL` 使用宿主 `extension-tool(.exe)` 的绝对路径。子模块自动探测相邻宿主 debug 路径，独立检出显式设置；构建步骤见 [工具准备](./development.md#准备宿主校验工具)。

未知 fixture 断言或清单字段时，核对实际宿主提交并重新编译工具。

### Rust 目标或插件产物缺失

在市场目录使用 [锁定工具链](../rust-toolchain.toml) 运行 `rustup target add wasm32-unknown-unknown`，检查 `RUSTUP_TOOLCHAIN` 没有覆盖选择。`build.json` 的文件名须对应 Cargo 实际库名，产物位置以 target-dir 为准。

按失败阶段修复锁文件、格式、源码或宿主契约，再编译当前 Wasm 并运行检查。

### 已存在相同修订目录

`Release directory already exists` 表示 `artifacts/market-<revision>` 已存在。保留旧产物，换未使用的修订重新构建。正式发布还须高于历史及客户端已见修订；改目录名不会改变签名 payload。

## CI 与生产发布

### 宿主工具准备长时间没有进展

展开 `host-tool`，用日志时间戳区分 APT、pnpm 和 Rust 编译。APT 的 `Ign` 先按镜像网络排查；[宿主工具 action](../.github/actions/host-tool/action.yml) 配有超时与重试。保留失败日志后修复原因再重跑。

### PR CI 使用了旧宿主或无法检出 ref

按 [固定配套宿主](./publishing.md#固定配套宿主) 核对 `STARTER_HOST_REF`、本次 `host_ref` 和摘要 SHA。确认提交已推送且可读；发布输入只覆盖本次发布，PR CI 仍使用仓库变量。

### 生产 Secret 缺失或与公钥不匹配

`Signing key does not match public-key.txt` 表示私钥缺失或与公钥不匹配；无效 PEM 或不可读 `MARKET_KEY_FILE` 会报告对应错误。核对 Secret、仓库外文件和密钥配对，保留密钥值私密。`check` 使用临时测试密钥，生产轮换按 [公钥轮换](./publishing.md#下架回退与公钥轮换) 执行。

### revision 重复或发布目标 SHA 错误

| 错误                                                        | 处理                                                                                 |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `Market revision must increase`                             | 选择高于完整非草稿 Release 历史与客户端已见值的新修订，从构建开始执行                |
| `Release source must be a complete 40-character commit SHA` | 核对市场源码的 `GITHUB_SHA` / `MARKET_SOURCE_SHA`，前者优先；不用宿主 SHA 或短 SHA   |
| `Release tag does not match the reviewed source commit`     | 核对标签最终 commit；`--target` 不会改指向，使用未占用的更高修订或按草稿恢复流程处理 |

历史或标签 API 错误时先恢复读取，再按 [生产发布](./publishing.md#actions-生产发布) 核对来源与修订。

### 上传失败或只看到草稿

核对日志和草稿附件，再按 [生产发布](./publishing.md#actions-生产发布) 处理已有草稿后重试。已公开的问题使用更高修订修复或下架。

## 数据保留与求助

排查期间保留注册表、私有存储、凭据和信任记录。旧开发版注册表使用宿主确认归档流程；未来或损坏数据保留原件，数据目录由应用管理。

普通 bug 提供本页开头的版本与错误信息、复现和脱敏日志；安全问题使用 [私密报告渠道](./security.md#漏洞与密钥事件)。
